# 模型级调度实施计划

2026-10-02。用户授权独立记录本任务，不覆盖原订阅计划。本阶段本地实现、测试及审查，不推送、不切换生产。

## 业务契约

- 只在现有权限过滤后的渠道集合内择优；订阅、令牌指定渠道及严格会话绑定保持原路由，不改计费。
- 统计按分组、请求模型、上游模型、接口、流式模式和推理强度隔离。流式计时使用有效文本或工具增量，不把元数据当首内容。
- 原渠道配置权重不修改。两次可归因失败将该模型健康权重系数降至 10%；两次串行有效成功解除降级，健康权重系数恢复 100%。实时速度/可靠性/负载评分仍决定最终分配概率，并非保证固定流量占比。客户端取消/无效参数不触发降级，429 单独冷却。
- active 纳管池默认跨静态优先级比较；`MODEL_ROUTING_PRIORITY_GROUPS` 可指定仍遵守主备优先级的分组。分组边界永不越过。
- 数据过期不视为零延迟；探索比例 5%，请求完成持续更新。独立 `model_routing_probe` 任务每 15 分钟执行，沿用既有并发配置，每渠道每轮最多 4 个 scope：降级预留2、近期请求预留1、其余轮转预留1；空位依此顺序补齐，同类最久未探测优先、同轮去重。不承诺每个 scope 都在每轮探测。探针只贡献健康判定，不混入真实延迟、TPS或错误率样本。旧自动探针不重复探测纳管 Enabled 渠道，手动全测仍可包含它们。
- 默认 off；shadow 只观测，active 才择优。显式分组/模型名单限定范围。Redis 失败回退原选路；所有副本使用 Redis 原子状态与有期限的在途租约。
- 本轮先交付后端核心及管理员只读诊断 API；前端评分面板单列后续，不以 API 代替 UI 验收。

## 分段与验证

1. 基础状态机和评分：先失败测试，模型隔离、过期、并发旧结果、两败两胜、数据不足、错误归因。复用既有 Redis 客户端，无数据库迁移。
2. 同时接入内存与数据库候选路径、HTTP relay 每次上游尝试及有效流输出采样。权限/固定渠道路径回归。
3. 既有探针接入模型健康反馈，避免与渠道级降权互相覆盖；管理员读取候选状态，不返回密钥/请求内容。
4. 运行聚焦、完整后端、构建与独立审查；保存实际结果及未验收项。无生产连接或真实上游付费压测。

开源仅借鉴思路，本次实现不复制上游源文件；固定参考版本见知识库《按模型跨渠道智能调度的十个开源参考》。

## 后续验收与发布计划（2026-10-02，实施中）

用户已批准本地实现与隔离验收；本阶段不推送、不部署。继续使用本目录，不覆盖订阅任务。以下测试必须对应同一个冻结的源码版本；旧版本通过不代替新版本验收。实际结果见 acceptance.md，未通过门槛前不执行D/E生产阶段。

### A. 校准契约与可复现基线

- 核对 git diff、已有测试和配置，记录源码版本及工作区差异。保留所有未提交改动。
- 恢复语义以用户原要求为准：连续两次合格成功恢复原健康权重系数；原“先恢复50%、再逐步恢复”实现已于本轮移除，回归测试先失败后通过。
- 明确每15分钟启动一轮与每模型每15分钟都探测的区别：当前每渠道最多4个scope轮转；实际请求持续采样。记录模型数量、覆盖时间和探针预算，不承诺超出预算的全量扫测。
- 核对原渠道权重、显式主备分组、模型映射及推理参数隔离；评分不能修改请求模型、权限、订阅绑定或钱包扣费。
- 验证：形成需求→测试对照表。依赖：无。涉及：本任务文档和现有相关测试，约2–3文件。

### B. HTTP全链路模拟上游验收

- 使用真实网关路由、鉴权及候选选择，接入本地可控快/慢/失败模拟服务，不连接付费上游。覆盖chat/completions、responses、messages及流式/非流式。
- 在同模型同分组下证明快且稳定的渠道得到更高分配概率；使用可重复样本与预先定义的容差，不把每次一定选最快作为标准。失败、恢复、429、取消、重试逐次核验归因。
- 验证跨模型互不污染、分组/指定渠道/严格会话/订阅边界不变；使用隔离账号与账本核验预扣、结算、退款及不静默转钱包。
- 验证：保存模拟服务收到的渠道/模型、网关请求记录和诊断结果；失败先写复现测试再修复。依赖：A。涉及：优先扩展现有controller/service集成测试，约3–5文件。

### C. 真实Redis多进程验收

- 使用两个独立网关进程及专用Redis实例或隔离命名空间，证明共享失败/恢复状态、在途请求和评分；不以miniredis或同进程两个Engine替代。
- 覆盖并发回报、重复完成、旧代际回报、进程退出、租约过期、Redis中断与恢复；验证旧选路回退不越权、不重复扣费。
- off/shadow/active各做预热及三轮同负载测量，记录p50/p95/p99调度附加耗时、吞吐、Redis错误和资源占用。拟定本地准入预算：附加p95≤10ms且吞吐下降≤5%；未达标先定位，不事后放宽掩盖结果。
- 验证：真实多进程运行记录及对比表。依赖：B。涉及：隔离测试脚本与现有回归，约2–4文件。

### D. 生产只读核对与启用清单

- 核实实际模型ID和渠道映射，不把聊天简称直接写入配置；核对分组、固定渠道、主备池、旧探针零权重及运行副本版本。
- 核对Redis连通与命名空间、任务执行节点、探针账号和预算；明确哪些模型参与，哪些保持原规则。
- 只读输出差异清单；不自动恢复历史零权重、不改渠道30分组、不改价格/用户余额。依赖：本地放行。无生产写入。

### E. 发布、观察及灰度

- 发布前读取工作区发布手册；冻结提交→Git推送→CI成功→构建不可变镜像，核对digest与revision。备份数据库并验证可恢复，保留当前线上镜像/容器。
- shadow先观察而不改变实际选路；验收其没有自动降权/改配置副作用。低流量没有足够样本时继续观察，不按等待时间直接放行。
- 按已核实的模型/分组白名单小范围active；保证服务副本使用一致配置。以错误率、首有效输出延迟、调度耗时、扣费和隔离情况决定扩展。
- 发生错误扣费、越权、错误跨模型或认证异常立即停止灰度，恢复旧应用及路由，保留账本和日志；不恢复旧数据库快照覆盖新消费。
