## 执行边界

- 本阶段开发与审查，禁止连接生产数据库进行测试，禁止发布生产镜像或发售卡密。
- 保留已有 redemption.go 草稿并修正，不覆盖历史生产任务文档。
- 用户曾要求卸载本地 Go；本次不重新安装或下载工具链。
- 套餐日4.90/周29.90/月89.90、每日输入50M/输出10M仅为原文档候选值，不代表已证明2%利润。
- 订阅只服务渠道24和 deepseek-v4.1-flash。普通余额仍按既有权限消费其他模型；不得静默用余额补订阅不足。

## 分阶段交付

1. 兑换核心：钱包/订阅类型分离、32字符卡密兼容、有效计划与用户验证、事务和并发兑换测试。验收：错误卡型不能兑换，重复兑换只成功一次，钱包金额不变。由高级程序员负责 model 层。
2. 管理与用户 API：服务端生成卡密、鉴权兑换、限流和脱敏审计。依赖1和计划服务绑定设计；不得只增加能发卡的入口而让资金路由未隔离。
3. 计费隔离：计划/订阅保存服务限制与每日输入输出额度；最终选渠及重试路径强制检查；预扣/结算/退款幂等；禁止Auto与客户端字段绕过。依赖1；覆盖并发、跨日、到期、上游失败和断流。
4. 前端接入：从鉴权API取真实数据，分别展示钱包与订阅；兑换入口可识别错误类型；购买链接只能指向真实已配置商品。
5. 隔离验收：Go构建与测试，SQLite/MySQL/PostgreSQL真实实例及升级迁移验证，浏览器完整兑换消费流程，输出证据后才评估发布。

## 第一阶段检查点

代码完成不等于功能可上线。无Go工具链时测试只能标记未执行；接口未接入、路由未硬隔离、真实成本未对账均为发布阻断项。生产版本匹配及独立测试运行环境须在部署前落实。

## 关键设计风险

- 现有订阅主要按统一额度计费，不能直接当作独立输入/输出Token双限额实现。
- 生成的订阅卡不能超过现有char(32)，也不能依赖前缀代替数据库卡型检查。
- 不能以调用方传入的渠道/模型作为授权依据。
- 不能用生产用户、令牌或数据库替代测试夹具。

### 推荐发布路径

1. **确定可回归的源码基线**：对齐香港现有 master 与定制 slave 的倍率、会话、计费行为；单独整理 V1 提交并包含路由，保留颜色修复。禁止用上游源码直接覆盖定制二进制。
2. **完成消费闭环**：接通最终渠道/模型检查、双额度预扣、结算和退款；同一请求重放不再次请求上游；不确定用量进入待对账，不能盲目全退。订阅固定渠道24和指定模型，其他模型仅使用显式钱包路径。
3. **隔离验收**：构建优先独立 CI，不在用户 Windows 安装工具链；香港仅在实时资源复核通过后运行限额验收容器。使用独立数据库、缓存空间、测试账户和最小权限凭据；默认模拟上游，真实冒烟只用受控小额测试密钥。不可复制生产秘密或把测试接到正式库。完成格式、编译、竞态、三库迁移/并发、钱包回归和浏览器端到端检查。
4. **管理员试用**：建议 test.lpss.online，DNS/TLS 尚未配置。独立容器/数据库，不加入生产请求池。入口额外访问保护，服务端所有 V1 入口和消费路径须角色/白名单双重检查，不能只隐藏按钮。先使用管理员测试身份，不发售卡密。
5. **生产小范围启用**：准备经恢复演练的备份、旧镜像摘要和配置；仅做向后兼容新增迁移。先部署兼容代码且 V1 默认关闭；全部可能处理订阅的副本必须支持同一账本和路由规则，不能让 V1 请求随机落到旧 slave。会话、加密配置一致，后台任务单例；流式请求排空后逐个更换副本。之后只向管理员/指定测试账户开启。
6. **正式销售**：管理员验收并确认价格、限额和最坏满额成本后再开放日/周/月卡；商品 SKU 与套餐/卡型绑定，少量生成正式库存，不混入测试卡。

### 回滚与放行

- 出现重复扣费、越权渠道、异常退款或钱包误扣，立即关闭新兑换和新 V1 请求；停止新增预扣，并完成或对账在途请求。
- 不通过恢复旧数据库快照回滚日常版本，否则会覆盖上线后余额与消费记录。账本保留；仅在确认旧程序不会误消费新订阅后回退镜像。
- 管理员隔离验收与正式上线是两个独立放行点；没有验收证据不发售。当前日期/额度候选值不代表利润承诺。
- 前端应固定同一资源版本或独立静态发布，避免重复出现混用脚本；不得改变现有普通 API 用户的默认入口。
