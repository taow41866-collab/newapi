## 长期修复（本地实现，待发布）

根因：原分组名称同时是路由和鉴权标识，可视化编辑仅替换配置键，令牌、渠道、订阅引用仍保留旧值，删除旧配置后出现 403。

- 新增 GroupDisplayNames，将可编辑显示名称与稳定分组标识分离；已保存标识不随改名变化，共用选择器提交原标识。
- Root 使用 PUT /api/group/settings 一次事务保存实际改变的分组字段；显示名校验失败不部分更新倍率。仅改显示名不回写页面中的旧倍率。
- 拒绝删除仍被用户、令牌（含自动组）、渠道、abilities、订阅升级/回退引用的标识。
- 旧 GroupRatio 两种配置键统一 canonical 优先，重载不被过时或损坏的旧别名覆盖。
- GET /api/group/display-names 使用 UserAuth，普通用户仅见当前可用组；PAT 读取 profile:read，写入 option:write 且仍需 Root。
- 保存失败保留草稿；保存期间继续编辑不会丢失；切换账号后迟到响应不发布原账号名称。

## 回滚边界

按私有快照中的主键仅回写对应分组字段，并核对配置和权限；不能恢复整个数据库快照或覆盖新消费记录。只回滚引用会再次出现旧分组鉴权故障，须先决定配置映射如何配套恢复。

`recover.py` 为本次定向恢复脚本，默认只读；`--apply` 会修改已固定目标，不能用来处理其他分组。后续运行前必须重新核实线上状态。
